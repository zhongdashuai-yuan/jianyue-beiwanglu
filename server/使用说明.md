# 班级通告 · 使用说明

给「备忘录提醒」加的一个小功能：**老师在电脑上发通告或作业，同班同学的程序自动收到。**

适用于**课前发、同学在校时收**这个场景。全部跑在局域网里，不依赖任何云服务，也不用花钱。

---

## 一、老师要做的（3 步）

### 1. 启动服务端

在项目目录里打开终端，执行：

```bat
python server\server.py
```

第一次运行会打印出**两个密钥**和一个**服务器地址**：

```
★ 管理员密钥（只有你自己知道，能发通告/任务）:
    ADMIN-XXXXXXXX

★ 接入密钥（发给同学，只能收）:
    MEMO-YYYYYY

同学要填的服务器地址（把能连上的那个发给他们）:
    192.168.1.5:8765
```

> ⚠️ 上面这两个密钥是**示例**，你的程序每次会随机生成自己的。
> 真实密钥只在你的终端里显示、只存在你自己电脑的 `server/server_data/class.db` 里，
> **不要把真实密钥发到公开的地方**（群公告、GitHub、聊天记录）。
> 接入密钥泄了最多被人看通告；**管理员密钥泄了，别人就能以你的名义发内容**。

> **两个密钥的区别**（很重要）：
> - **管理员密钥**：能发通告、发作业、撤回。**只你自己留着**，别发给同学。
> - **接入密钥**：同学拿它只能"看"，不能发。发给全班没问题。

**这个窗口要一直开着**（可以最小化）。关掉服务，同学就同步不到了。

### 2. 让同学的电脑能连上

同学填的地址要用**你电脑在局域网里的 IP**。如果不知道是哪个，服务端启动时会打印出来，通常是 `192.168.x.x` 这种。

**如果同学连不上**，多半是 Windows 防火墙拦了。在**管理员** PowerShell 里执行一次（只需一次）：

```powershell
New-NetFirewallRule -DisplayName "备忘录班级服务" -Direction Inbound -Protocol TCP -LocalPort 8765 -Action Allow
```

### 3. 发通告 / 发作业

老师端的管理界面**还没做**，现在用命令行发（够用且稳）：

**发一条通告**（同学在「班级」页看到）：

```bat
python server\send.py announcement "明天交作业" --body "第 3 章习题，拍照上传到群里"
```

**发一个班级任务**（会进同学的待办列表，并按时提醒）：

```bat
python server\send.py task "周四交实验报告" --date 2026-10-08 --time 08:00 --priority 高
```

**看谁装了、谁最近同步过**：

```bat
python server\send.py members
```

**撤回发错的内容**：

```bat
python server\send.py list                 :: 先看有哪些，拿到 id
python server\send.py withdraw-ann 3       :: 撤回 3 号通告
python server\send.py withdraw-task 2      :: 撤回 2 号任务
```

> `send.py` 会自动读服务端数据目录里的密钥，所以你**不用每次输密钥**。

## 二、同学要做的（1 步，只做一次）

1. 打开备忘录程序 → 左下角 **设置**
2. 找到「**班级通告（老师发、同学收）**」这一段
3. 填两项（老师会在群里发给你）：
   - **服务器地址**：`192.168.1.5:8765`（要加 `http://`，即 `http://192.168.1.5:8765`）
   - **接入密钥**：`MEMO-YYYYYY`（换成老师给你的那个）
   - **你的名字**：可以留空；填了老师能在服务端看到谁接入了
4. 点「**测试连接**」→ 显示「✓ 连接成功」就对了 → 点「保存」

之后程序会**每 3 分钟自动同步一次**，左侧「班级」那一项上会出现未读数，比如 `📣 班级 (2)`。

## 三、常见问题

**Q：老师电脑关机了，同学还能看到通告吗？**
能。**已经同步下来的**通告和任务存在同学自己电脑里，老师关机不影响。
但老师**关机期间发的新内容**，同学收不到 —— 等老师下次开机才会收到。

**Q：同学能改老师发的作业吗？**
- 老师发的**通告**：只能看和标记已读，改不了
- 老师发的**任务**：能勾完成、能稍后提醒，但**不能删除**（防止误删作业）；
  要让它消失只能老师撤回

**Q：同学能冒充老师发通告吗？**
不能。发通告需要管理员密钥，同学手里的接入密钥只能读（服务端会返回 403）。

**Q：老师发的作业和同学自己加的任务会混吗？**
不会。老师发的在卡片上有「**老师**」小标签，来源分开存放，各自独立。

**Q：需要联网/买服务器吗？**
不用。服务端就跑在老师电脑上，同学在学校网络里就能连。
**但如果老师想"发完就关机、同学随时能收"，就必须把服务端放到一台常开的机器上**（云服务器或学校服务器）—— 老师电脑当服务器时，"开关机时间"就是"通告的可见时间"。

**Q：能不能发到校外（同学在家也能收）？**
现在不行。这是局域网服务，同学要和老师在同一网络里。要支持校外，得把服务端放到有公网地址的机器上，并把 `server.py` 启动参数改成 `--host 0.0.0.0`（已经是默认值），再用公网 IP 或域名。

## 四、安全须知（重要）

这个服务是**给班级内部用**的，设计上刻意保持简单，所以有几条限制必须知道：

| 项目 | 现状 | 建议 |
|---|---|---|
| 传输加密 | **没有 HTTPS**，内容明文传输 | 只在学校内网用，别暴露到公网 |
| 身份认证 | 靠两个密钥（共享口令） | 接入密钥别外传；每学期换一次 |
| 学生隐私 | 只记录"谁接入了、什么时候同步的" | 不收集完成情况；同学名字可以留空 |
| 数据内容 | 纯文本通告，**不会被当代码执行** | 别让通告内容能触发命令（现在做不到，安全） |

**密钥泄露了怎么办？** 删掉服务端数据目录里的 `class.db` 重新启动，会自动生成新密钥（但已发的通告也会丢，建议先备份）。
